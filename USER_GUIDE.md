## 1. Архитектура и ключевые возможности

FluxProxy спроектирован как современная замена классическим отладчикам веб-трафика (Fiddler Classic, Charles Proxy, Proxyman):

```
┌─────────────────────────────────────────────────────────────┐
│                   React 18 Frontend UI                      │
│   (Vite, TypeScript, Tailwind CSS, Monaco Editor, Virtual)  │
└──────────────────────────────┬──────────────────────────────┘
                               │  Tauri IPC (Commands / Events)
┌──────────────────────────────▼──────────────────────────────┐
│                    Tauri v2 Desktop Core                    │
│      (lib.rs, commands.rs, models.rs, sqlite storage)       │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                  Asynchronous MITM Engine                   │
│   ├── Hyper 1.x + Tokio (HTTP/1.1 & HTTP/2 Server/Client)   │
│   ├── Tokio-Rustls + rcgen + Moka (On-the-fly ECDSA CA)     │
│   ├── Tokio-Tungstenite (WebSocket Interception)            │
│   ├── Breakpoints & Rules Engine (Live Pause & Modify)      │
│   ├── SysProxy Controller (OS Proxy Auto-Configuration)     │
│   └── Process Resolver (PID / App Path Identification)      │
└─────────────────────────────────────────────────────────────┘
```

- **Асинхронное ядро на Rust**: прозрачный перехват и мультиплексирование потоков HTTP/1.1 и HTTP/2 через `hyper-util`.
- **Генерация сертификатов на лету**: использование быстрых ECDSA P-256 сертификатов через библиотеку `rcgen` с LRU-кэшированием в памяти (`moka`).
- **Перехват WebSocket (WS/WSS)**: перехват и разбор каждого кадра с опкодами, направлением и содержимым.
- **Инспекция Server-Sent Events (SSE)**: разбор потока событий в реальном времени с автоматической сборкой связного текста генераций нейросетей (OpenAI, Anthropic, Gemini).
- **Виртуализированный UI**: бесперебойные 60 FPS при работе с базой в 10 000+ сессий благодаря `@tanstack/react-virtual`.
- **Интеграция с Monaco Editor**: полноценный просмотр и редактирование JSON, XML и тел запросов с подсветкой синтаксиса и форматированием.

## 2. Управление перехватом и сетевые режимы

FluxProxy функционирует как локальный HTTP/HTTPS/WebSocket прокси-сервер (по умолчанию адрес: `127.0.0.1:8888`).

### Основные переключатели (TopToolbar / Menu / Палитра):

| Действие | Горячая клавиша | Описание |
| :--- | :--- | :--- |
| **Capture Traffic** | `F12` | Включает или приостанавливает сетевой захват прокси-сервером. |
| **OS System Proxy** | Меню `File` / Статус-бар | Автоматически прописывает FluxProxy в качестве системного прокси ОС (Windows Internet Settings, macOS Networksetup, Linux). |
| **Attach on Startup** | Меню `File` | Опция автоматического включения системного прокси при каждом запуске программы. |
| **Allow Remote (0.0.0.0)**| `Ctrl+Shift+M` / Меню `File` | Разрешает входящие подключения с внешних устройств (смартфоны, планшеты, соседние ПК в LAN). |

> [!NOTE]
> При выходе из приложения или нажатии `F12` FluxProxy автоматически и гарантированно возвращает оригинальные настройки системного прокси ОС.

## 3. Расшифровка HTTPS (Root CA и MITM)

Для расшифровки защищенного TLS-трафика FluxProxy генерирует локальный удостоверяющий центр (Root CA).

### Установка сертификата:
1. Нажмите на иконку **щита с замком** в левом нижнем углу или выберите **Tools → HTTPS Root CA Certificate...** (также доступно через `Ctrl+K` → *"Inspect or Install HTTPS MITM Root CA"*).
2. Нажмите кнопку **Trust Root CA in OS Store**:
   - **Windows**: сертификат устанавливается в хранилище *«Доверенные корневые центры сертификации»* текущего пользователя через команду `certutil`.
   - **macOS**: сертификат добавляется в системную связку ключей *System Keychain* с доверием SSL через утилиту `security`.
   - **Linux**: сертификат копируется в `/usr/local/share/ca-certificates/` с вызовом `update-ca-certificates`.
3. При необходимости скопируйте пути к файлам `ca.crt` (DER) или `ca.pem` для добавления в браузеры с изолированными хранилищами (Firefox) или в контейнеры/эмуляторы.

## 5. Таблица трафика (TrafficGrid)

Таблица отображает поток перехваченных сессий в режиме реального времени.

### Доступные колонки:
1. **ID** (`#`): уникальный возрастающий порядковый номер сессии.
2. **Status**: HTTP статус-код (с цветовой градацией 2xx — зеленый, 3xx — синий, 4xx — желтый/оранжевый, 5xx — красный) либо статус ожидания `WAIT` при срабатывании точки останова.
3. **Method**: метод запроса (`GET`, `POST`, `PUT`, `DELETE`, `PATCH`, `OPTIONS`, `CONNECT` и др.).
4. **Protocol**: протокол передачи данных (`HTTP/1.1`, `HTTP/2`, `WS`, `WSS`).
5. **Host**: целевой домен и порт сервера.
6. **URL / Path**: путь запроса и query-параметры.
7. **Process**: имя процесса-источника и его PID (например, `chrome.exe:14208`, `node.exe:8840`) или IP-адрес удаленного клиента (`192.168.1.105`).
8. **Size**: объем тела ответа в байтах, килобайтах или мегабайтах.
9. **Time**: длительность выполнения запроса в миллисекундах с цветовой индикацией.
10. **Comment**: пользовательский текстовый комментарий или пометка.

### Индикаторы и бейджи в ячейке URL:
- `BP:REQ` / `BP:RES`: сессия поставлена на паузу точкой останова (до отправки или после ответа).
- `BP-MOD`: сессия была вручную изменена разработчиком на точке останова.
- `BYPASS`: соединение прошло сквозным TCP-пробросом (без расшифровки TLS).
- `MOCK`: ответ сгенерирован правилом AutoResponder.
- `HDR`: заголовки сессии были автоматически модифицированы движком правил.
- `💬`: к сессии добавлен пользовательский комментарий.

### Цветовая карта времени (Time Heat Map):
- ⚠️ **Slow Request** (по умолчанию $\ge 500$ ms): подсвечивается оранжевым с иконкой пламени.
- 🔴 **Critical Latency** (по умолчанию $\ge 1500$ ms): подсвечивается красным бейджем.
- Пороги настраиваются во вкладке *Filter Drawer → Thresholds*.

### Настройка колонок:
- **Изменение ширины мышью**: потяните за границу заголовка колонки.
- **Автоподбор ширины (Auto-fit)**: дважды кликните по разделителю колонки. Ширина автоматически адаптируется под самый длинный текст в видимых строках.
- **Управление видимостью**: кликните правой кнопкой мыши по заголовку таблицы (*Header Context Menu*) для включения/выключения колонок.

### Контекстное меню сессии (Right Click):
- **Replay запрос (`R` / `Ctrl+R`)**: немедленно повторить запрос в upstream.
- **Открыть в Composer**: загрузить метод, URL, заголовки и тело в конструктор запросов.
- **Сравнить в Session Diff (`Ctrl+D`)**: сравнить две выбранные сессии в визуальном diff-редакторе.
- **Copy URL (`Ctrl+C`)**: скопировать полный URL одной или нескольких выделенных сессий.
- **Copy as cURL**: скопировать готовую исполняемую строку команды `curl` с заголовками и телом.
- **Copy Request/Response Headers**: скопировать блок HTTP-заголовков.
- **Комментарий / Маркер (`M`)**: задать цвет заливки строки и ввести комментарий.
- **Снять цветовую метку (`U`)**: очистить выделение.
- **Создать правило AutoResponder**: создать мок-правило на основе текущего запроса и ответа.
- **Фильтровать по процессу / IP**: моментально оставить в списке только трафик выбранного приложения или мобильного клиента.
- **Always inspect / Always passthrough**: быстро добавить хост в целевой список расшифровки или в TLS Bypass.
- **Удалить (`Delete` / `Backspace`)**: удалить сессии из таблицы.

## 6. Многофункциональный инспектор сессий (Session Inspector)

Инспектор сессий активируется при выборе любой строки в таблице. Верхняя часть инспектора отвечает за **Request (Запрос клиента)**, нижняя — за **Response (Ответ сервера)**. Направление разделения (горизонтальное / вертикальное) переключается кнопкой в тулбаре инспектора.

---

### 6.1 Вкладки инспектора запросов (Request)

| Вкладка | Назначение |
| :--- | :--- |
| **Headers** | Список всех переданных HTTP-заголовков в удобном табличном виде с кнопками копирования значений. |
| **Params** | Автоматически распарсенные Query-параметры URL с декодированием спецсимволов. |
| **Cookies** | Разобранные Cookie клиента, отправленные в заголовке `Cookie`. |
| **Auth** | Инспектор авторизации: автоматический разбор Basic Auth, Bearer токенов, API-ключей и встроенный аудит безопасности. |
| **Multipart** | Разбор составных форм `multipart/form-data` и `application/x-www-form-urlencoded` с предпросмотром загруженных файлов и изображений. |
| **gRPC / Proto** | Декодирование бинарных сообщений Protobuf и gRPC wire format без необходимости иметь `.proto` файл. |
| **Raw** | Необработанный сырой текст HTTP-запроса по спецификации RFC. |
| **JSON** | Форматированный просмотр и валидация JSON-пейлоада в редакторе Monaco Editor. |
| **XML** | Подсветка синтаксиса и форматирование XML / SOAP / SVG. |
| **Hex** | Шестнадцатеричный дамп байтов тела запроса с синхронизированным ASCII-представлением. |

---

### 6.2 Вкладки инспектора ответов (Response)

| Вкладка | Назначение |
| :--- | :--- |
| **Headers** | Заголовки ответа сервера с кодом и описанием статуса. |
| **Cookies** | Куки, выставляемые сервером через заголовки `Set-Cookie`, с отображением флагов безопасности (`Secure`, `HttpOnly`, `SameSite`, `Domain`, `Path`, `Expires`). |
| **Caching** | Глубокий анализ кэширования: расчет TTL, статус свежести, анализ `Cache-Control`, `ETag`, `Expires`, `Last-Modified`, `Age`. |
| **Auth** | Инспекция заголовков аутентификации сервера (`WWW-Authenticate`). |
| **SSE** | Инспектор потоковых событий `text/event-stream` с реконструкцией ответов нейросетей. |
| **WS** | Таблица фреймов WebSocket соединения в реальном времени. |
| **gRPC / Proto** | Декодирование gRPC ответов, включая статус завершения (`grpc-status`, `grpc-message`). |
| **Raw** | Сырой текст HTTP-ответа сервера. |
| **JSON** | Форматированный JSON-ответ в Monaco Editor с возможностью поиска и копирования. |
| **XML** | Просмотр XML-ответов с древовидной подсветкой. |
| **Image** | Визуальное превью графических форматов (`PNG`, `JPEG`, `GIF`, `WEBP`, `SVG`, `ICO`) с отображением разрешения и размера. |
| **Hex** | Шестнадцатеричный просмотр бинарных данных ответа. |

### 6.3 Специализированные протокольные анализаторы

#### 1. Инспектор потоков SSE (Server-Sent Events) и LLM Streaming
При отладке потоковых ответов (например, эндпоинтов OpenAI `/v1/chat/completions`, Anthropic, Gemini):
- Отображает общее число чанков, суммарную длительность потока и объем данных.
- **Кнопка «Собрать весь стрим LLM в один текст»**: объединяет разрозненные дельты токенов из JSON-чанков в единый итоговый связный ответ модели.
- Таблица чанков с точным временем смещения (`+ms`), типом события (`event`) и сырыми данными (`data`).
- Просмотр каждого чанка в Monaco Editor.

#### 2. Инспектор WebSocket фреймов
- Отображает хронологический список всех отправленных (`↑ Client`) и принятых (`↓ Server`) фреймов.
- Поддерживает декодирование опкодов: `Text`, `Binary`, `Ping`, `Pong`, `Close`.
- Показывает точный размер в байтах и превью полезной нагрузки.

#### 3. Анализатор Protobuf и gRPC
- Автоматически распознает `application/grpc`, `application/grpc+proto`, `application/x-protobuf`.
- Умеет принудительно декодировать произвольные бинарные байты как Protobuf wire-format.
- Поддерживает два режима просмотра:
  1. **Wire Fields Table**: разбор полей по их номерам тэгов (Tag #), типам данных (Varint, Length-Delimited, 32-bit, 64-bit), альтернативным интерпретациям (Signed Int, Float, Double) и смещениям.
  2. **JSON Projection**: автоматическая проекция структуры Protobuf в валидный читаемый JSON в Monaco Editor.

#### 4. Анализатор авторизации и безопасности (Auth Inspector)
- Декодирует токены `Bearer`, `Basic`, `Digest`, заголовки `X-API-Key`.
- Проводит автоматический аудит безопасности:
  - 🚨 *Критическая ошибка*: передача учетных данных Basic Auth по незашифрованному HTTP протоколу.
  - ⚠️ *Предупреждение*: истекший срок действия JWT токена (`exp`), слабый алгоритм подписи (`none`, `HS256`).
  - ℹ️ *Информация*: корректный активный токен в защищенном канале TLS.
- Кнопка **«В TextWizard»** для мгновенного переноса токена в специализированный декодер.

#### 5. Анализатор форм и вложений (Multipart Inspector)
- Разбирает составные части `multipart/form-data` по boundary.
- Отображает имена полей, имена загружаемых файлов, типы контента.
- Для прикрепленных изображений рендерит визуальное мини-превью прямо внутри таблицы частей формы.

## 7. Интерактивные точки останова (Live Breakpoints)

Точки останова позволяют приостанавливать выполнение сетевого запроса и интерактивно изменять его параметры до того, как пакет уйдет в сеть или дойдет до клиента.

```
Клиент (Браузер) ──► [ Break Before Request ] ──► Upstream Сервер
                              (F11)
                                │
                              Модификация метода, URL, Headers, Body в Monaco
                                │
Клиент (Браузер) ◄── [ Break After Response ] ◄── Upstream Сервер
                            (Alt+F11)
                                │
                              Подмена Status Code, Headers, Response Body
```

### Режимы перехвата:
1. **Break Before Request (`F11`)**: соединение ставится на паузу перед отправкой на реальный сервер. Вы можете изменить HTTP-метод, адрес назначения, отредактировать заголовки или переписать JSON-пейлоад в Monaco Editor.
2. **Break After Response (`Alt+F11`)**: ответ сервера перехвачен до попадания в браузер. Вы можете подменить статус-код (например, вернуть 500 вместо 200), переписать тело ответа или добавить заголовки.
3. **Условные точки останова (`bpu` / `bpafter`)**: срабатывают только при совпадении URL с заданным паттерном.
   - Быстрая команда в Command Palette (`Ctrl+K`):
     - `bpu /api/v1/orders` — перехватывать запросы, содержащие данный путь.
     - `bpu` — отключить все условные точки останова запросов.
     - `bpafter /checkout` — перехватывать только ответы по указанному пути.
     - `bpafter` — сбросить точки останова ответов.
4. **Снять все точки останова (`Shift+F11`)**: мгновенно отключает все перехваты и отпускает зависшие пакеты.

### Окно перехватчика (Breakpoint Interceptor):
- Автоматически открывается при захвате подходящего сетевого пакета.
- Показывает обратный отсчет таймаута сессии.
- Кнопки быстрой эмуляции кодов ошибок: **500 Internal Server**, **403 Forbidden**, **404 Not Found**, **502 Bad Gateway**.
- Действия:
  - **Execute / Continue**: применить сделанные правки и отправить пакет дальше.
  - **Drop / Abort**: разорвать соединение с клиентом (эмуляция сетевого сбоя).
  - **Resume All**: выпустить все накопившиеся в очереди сессии.

## 8. AutoResponder — мокирование и правила подмены

AutoResponder позволяет создавать правила автоматического ответа на сетевые запросы без необходимости писать код на бэкенде.

### Настройка правил:
- **Условия совпадения (Match Target)**:
  - `urlContains`: вхождение подстроки в URL (например, `/api/users`).
  - `urlRegex`: регулярное выражение (например, `^https://api\.example\.com/v[0-9]+/items/\d+$`).
  - `headerMatch`: проверка наличия или значения определенного заголовка.
- **Фильтр по методу**: `ANY`, `GET`, `POST`, `PUT`, `DELETE` и др.
- **Типы действий (Action Type)**:
  - `mockResponse`: вернуть заранее заготовленный статус (200, 201 и т.д.), кастомные заголовки (`Content-Type: application/json`) и тело ответа, заданное в Monaco Editor.
  - `overrideStatus`: переопределить только статус ответа (например, вернуть 429 Too Many Requests).
  - `delayOnly`: пропустить запрос на реальный сервер, но искусственно задержать его на заданное количество миллисекунд (эмуляция медленного 3G/Edge соединения).
- **Искусственная задержка (Latency Ms)**: задается для любого правила (включая моки), позволяя тестировать лоадеры и спиннеры на фронтенде.

> [!TIP]
> Создать правило можно в один клик прямо из таблицы трафика: кликните правой кнопкой мыши по любой сессии и выберите **«Создать правило AutoResponder»**. Метод, URL и тело ответа скопируются автоматически!

## 9. Конструктор запросов (Request Composer)

Composer позволяет вручную собирать и отправлять произвольные HTTP-запросы для тестирования API.

### Возможности:
- **Выбор метода**: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`.
- **Редактор заголовков**: добавление, редактирование и удаление пар ключ-значение.
- **Редактор тела**: полнофункциональный Monaco Editor с автоформатированием JSON.
- **Опция Follow Redirects**: автоматический переход по 301/302 перенаправлениям.
- **Drag-and-Drop сессий**: перетащите любую строку из таблицы TrafficGrid прямо на панель Composer — метод, адрес, заголовки и тело подставятся автоматически.
- **Split Composer**: переключите режим через меню *View → Split Composer Pane*, чтобы видеть таблицу сессий и конструктор запросов одновременно на одном экране.
- **Немедленный просмотр**: результат выполнения запроса отображается прямо под формой с возможностью переключения между форматированным JSON и сырыми заголовками.

## 10. Сравнение двух сессий (Session Diff)

Встроенный визуальный инструмент сравнения сессий на базе **Monaco DiffEditor**.

### Способы открытия сравнения:
1. Выделите две сессии в таблице трафика с зажатой клавишей `Ctrl` (или `Shift`) и нажмите `Ctrl+D` (либо иконку весов в строке).
2. Нажмите `Ctrl+D` в любой момент — умный алгоритм автоматически подберет для текущей сессии парную сессию с тем же хостом и путем, но другим статусом ответа.

### Вкладки сравнения:
- **Full HTTP**: комплексное сравнение запроса и ответа целиком.
- **Headers**: построчный diff заголовков запроса и ответа.
- **Cookies & Auth**: сравнение переданных кук и разобранных клеймов JWT токенов.
- **Req Payload**: разница между параметрами и телами запросов.
- **Resp JSON / Body**: визуальное выделение изменений в JSON-ответах бэкенда.

### Опции нормализации:
- **Sort Keys & Headers**: автоматическая сортировка JSON-ключей и заголовков по алфавиту для исключения ложных различий при разном порядке полей.
- **Ignore Volatile Headers**: автоматическое скрытие избыточных динамических заголовков (`Date`, `Age`, `X-Request-Id`, `traceparent`), которые меняются при каждом вызове.
- **Side-by-Side vs Inline**: переключение между двухколоночным и построчным режимом сравнения.
- **Рокировка (Swap Pair)**: моментальная смена левой и правой стороны сравнения местами.

## 11. Text Wizard, JWT Decoder и компрессия

Многофункциональный швейцарский нож для работы с кодировками, криптографией и форматами данных (`Ctrl+E`).

### Доступные инструменты:

```
┌────────────────────────────────────────────────────────────────────────┐
│ Text Wizard & Codec Suite (Ctrl+E)                                     │
├─────────────┬───────────┬─────────────┬─────────────┬───────┬──────────┤
│ JWT Inspect │  Base64   │  URL Codec  │ Compression │  Hex  │Timestamp │
└─────────────┴───────────┴─────────────┴─────────────┴───────┴──────────┘
```

1. **JWT Inspector**:
   - Автоматически разбивает токен на Header, Payload и Signature.
   - Декодирует JSON-клеймы (`sub`, `iss`, `aud`, роли, права).
   - В реальном времени проверяет срок действия токена (`exp`), дату выпуска (`iat`) и начало действия (`nbf`).
   - Отображает обратный отсчет времени жизни токена и дату в локальном часовом поясе.
   - Поддерживает генерацию демонстрационного токена.

2. **Base64 Codec**:
   - Кодирование и декодирование текста и бинарных данных.
   - Поддержка стандартного Base64 и URL-Safe Base64 (`-` и `_` вместо `+` и `/`).

3. **URL Codec**:
   - URL-encode и URL-decode параметров и ссылок.
   - Режимы обработки отдельных компонентов (`encodeURIComponent`) и полных URI (`encodeURI`).

4. **Compression Codec (Gzip / Brotli / Deflate)**:
   - Сжатие и распаковка данных алгоритмами Gzip, Brotli, Deflate через асинхронное Rust-ядро.
   - Расчет коэффициента сжатия и сохраненного объема данных (bytes saved).
   - Вывод результатов в текстовом виде, Base64 или Hex.

5. **Hex ↔ Text Converter**:
   - Преобразование текста в шестнадцатеричный байтовый дамп и обратно.
   - Настраиваемый разделитель байтов: пробел, двоеточие (`:`) или сплошной поток.

6. **Timestamp ↔ ISO 8601**:
   - Конвертация Unix Epoch времени (секунды, миллисекунды, микросекунды) в ISO 8601 формат.
   - Отображение даты в UTC и локальном времени пользователя с расчетом относительного интервала (*«5 минут назад»*, *«через 2 часа»*).

## 12. Продвинутая система фильтрации (Filter Matrix & Hosts)

Панель фильтрации вызывается по кнопке **Filter** в тулбаре, через меню *Rules → Filter Matrix* (`Alt+4`) или через статус-бар.

### 1. Массовый фильтр хостов (Hosts List)
- Режим **Whitelist**: отображать в таблице трафика только сессии указанных хостов.
- Режим **Blacklist**: скрывать трафик указанных хостов.
- Поддерживает ввод списком, подмаски доменов (`*.google.com`, `api.internal.*`), точные адреса и пути.
- Опция **Apply to TLS Passthrough**: хосты, не попавшие в Whitelist, будут автоматически пропускаться ядром прокси сквозным туннелем без расшифровки, что снижает нагрузку на CPU.

### 2. Матрица условий (Filter Matrix)
Позволяет конструировать сложные логические цепочки условий:
- **Поля фильтрации**: `URL`, `Host`, `Path`, `Method`, `Status`, `ContentType`, `ProcessName`, `ProcessPID`, `ClientIP`, `Protocol`, `BodySize`, `Duration`, `Comment`.
- **Операторы**: `содержит`, `не содержит`, `равно`, `не равно`, `начинается с`, `заканчивается на`, `RegExp`, `>`, `>=`, `<`, `<=`.
- **Действия**: `Include` (включить) или `Exclude` (исключить).
- **Логическая связка**: `AND` / `OR`.

### 3. Готовые пресеты (Filter Presets):
- 🎯 **Только API бэкенда**: оставляет JSON, GraphQL и REST запросы, автоматически скрывая статические ассеты, CORS preflight и 304 ответы.
- 🔇 **Скрыть аналитику и шум ОС**: исключает системные службы обновления Windows/macOS, Google Analytics, telemetry, Sentry, Mixpanel.
- ⚡ **Медленные и тяжелые**: фильтрует запросы с латентностью $> 500$ ms, размером тела $> 1$ MB или кодами ошибок $5xx$.
- 💻 **Только Dev-клиенты**: отбирает трафик от локальных сред разработки (`node`, `python`, `postman`, `insomnia`, `curl`), отсекая браузеры.
- Возможность сохранять любые свои комбинации фильтров в качестве пользовательских пресетов.

### 4. Фильтрация фонового шума (Thresholds):
- Скрытие ответов `304 Not Modified`.
- Скрытие CORS preflight запросов (`OPTIONS`).
- Скрытие служебных туннелей `CONNECT`.
- Скрытие статических файлов (`.png`, `.jpg`, `.css`, `.js`, `.woff2`, `.svg`).
- Фильтрация по минимальному и максимальному размеру тела.

### 5. Выборочная расшифровка (Selective TLS MITM & Bypass):
- Режим **Intercept All**: расшифровывать весь HTTPS трафик, за исключением списка Bypass.
- Режим **Targeted Only (Allowlist)**: безопасный режим — расшифровывать **только** хосты из доверенного белого списка, весь остальной трафик ОС идет через сквозной TCP-туннель.
- **Пакеты быстрого обхода (Quick Packs)**:
  - Сервисы Apple и iCloud (где активен жесткий Certificate Pinning).
  - Центры обновления ОС Windows Update.
  - Мессенджеры (Telegram, WhatsApp, Signal).
  - Банковские и платежные шлюзы (Stripe, 3-D Secure, PayPal).

### 6. Мутации заголовков на лету (Header Mutations):
- Автоматическая модификация заголовков сетевым ядром Rust до отправки в сеть или до возврата в браузер.
- Операции: **Set** (установить/перезаписать), **Remove** (удалить), **Append** (добавить).
- **Встроенные готовые правила**:
  - *Force No-Cache*: автоматическое удаление заголовков `If-Modified-Since`, `If-None-Match`, `ETag`, `Last-Modified` для принудительного получения свежих ответов с сервера без кэша браузера.
  - *Подмена User-Agent*: пресеты популярных устройств (iPhone Safari, Android Chrome, Desktop Chrome, iPad, cURL, Googlebot).
  - *Инъекция CORS*: автоматическое добавление заголовков `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Headers: *` для локальной разработки фронтенда без конфликтов CORS.

## 13. Отладка мобильных устройств (iOS и Android)

FluxProxy позволяет в считанные секунды настроить перехват и инспекцию трафика со смартфонов и планшетов, находящихся в одной Wi-Fi сети с компьютером.

Мастер вызывается сочетанием клавиш `Ctrl+Shift+M` или через меню **Tools → Connect Mobile Device...**.

### Пошаговый сценарий:

1. **Сетевой интерфейс и режим 0.0.0.0**:
   - Мастер автоматически определит ваш локальный IP-адрес в Wi-Fi сети (например, `192.168.1.45`) и проверит порт (`8888`).
   - При необходимости включите опцию **«Разрешить подключения с удаленных устройств (0.0.0.0)»**.

2. **Настройка прокси на телефоне**:
   - Откройте свойства вашей Wi-Fi сети на смартфоне.
   - Переключите режим прокси в **Вручную (Manual)**:
     - Сервер / Прокси: IP-адрес вашего компьютера (например, `192.168.1.45`).
     - Порт: `8888`.

3. **Загрузка и установка Root CA сертификата**:
   - Отсканируйте камерой смартфона **QR-код** из окна мастера или откройте браузер на телефоне и перейдите по адресу:
     ```
     http://flux.proxy/cert
     # или
     http://<IP-вашего-компьютера>:8888/cert
     ```
   - **Для iOS**:
     1. Подтвердите загрузку профиля конфигурации.
     2. Перейдите в *Настройки → Профиль загружен* и нажмите **Установить**.
     3. Перейдите в *Настройки → Основные → Об этом устройстве → Доверие сертификатам* и включите полный тумблер доверия для корневого сертификата FluxProxy.
   - **Для Android**:
     1. Скачайте файл сертификата `.crt`.
     2. Перейдите в *Настройки → Безопасность → Шифрование и учетные данные → Установка с накопителя → Сертификат CA*.
     3. Подтвердите установку.
     4. Для приложений на Android 7+ (API 24+) скопируйте из мастера XML-конфигурацию `network_security_config.xml` для доверия пользовательским сертификатам в режиме отладки (`debug-overrides`).

4. **Фильтрация трафика смартфона в таблице**:
   - В колонке `Process` IP-адрес мобильного устройства помечается специальным зеленым бейджем со значком смартфона 📱.
   - Кликните по бейджу в таблице или выберите в контекстном меню **«Фильтровать по IP устройства»**, чтобы моментально изолировать трафик телефона от фонового шума компьютера.

## 15. Хранилище сессий (SQLite) и интеграция с CLI

### Локальное хранилище сессий (SQLite):
- FluxProxy поддерживает сохранение всей базы перехваченных сессий в локальный архив SQLite (`rusqlite` в высокопроизводительном режиме WAL).
- **Сохранение архива**: меню *File → Save Archive to SQLite* (или через `Ctrl+K`).
- **Восстановление архива**: меню *File → Restore Archive from SQLite* — восстанавливает все сохраненные сессии с полными заголовками, телами и метаданными для ретроспективного анализа.

### Интеграция с консольными утилитами:
Для направления трафика утилит командной строки через FluxProxy используйте переменные окружения:

#### Windows (PowerShell):
```powershell
$env:HTTP_PROXY="http://127.0.0.1:8888"
$env:HTTPS_PROXY="http://127.0.0.1:8888"
```
*(Скопировать готовую команду можно через меню **Help → Copy CLI HTTP_PROXY Snippet**).*

#### macOS / Linux (Bash, Zsh):
```bash
export HTTP_PROXY="http://127.0.0.1:8888"
export HTTPS_PROXY="http://127.0.0.1:8888"
```

#### Пример запроса через cURL:
```bash
curl -x http://127.0.0.1:8888 https://httpbin.org/get -k
```
